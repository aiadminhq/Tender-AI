02

開源選型 · 各領域首選

硬約束：本地優先 · 單機 · 零雲費 · 可被 FastAPI inline 整合
Learning-to-Rank / 偏好學習
★LightGBMMIT
原生 LGBMRanker + lambdarank position-bias 正則化，純 Python inline 推論可在 FastAPI 同進程 <10 行載入，與 pgvector 召回直接串聯——隱式回饋首選。
Agentic RAG / Agent 框架
★LlamaIndexMIT
原生為 RAG 而設計，一行切換本機 Ollama（bge-m3 / qwen3.5），PGVectorStore 直讀現有 pgvector，AgentWorkflow 可嵌入既有 NDJSON 串流後方——整合成本最低。
向量檢索 / Reranking
★bge-reranker-v2-m3MIT
與已落地的 bge-m3 embeddings 同源（BAAI），支援繁中，pip 一行嵌入 FastAPI，亦有 Ollama 社群映像可走現有 :11434。
行為 / 事件分析
★Umami v3MIT
PostgreSQL-only，直接共用現有 pg16+pgvector，零 ClickHouse/Kafka；REST API 讓 FastAPI 零依賴推送自訂事件，Cohort/Segment 對應「推理使用者衡量標準」。
通知 / 主動推播
★Apprise ＋ ntfyMIT / Apache-2.0
Apprise pip 直接嵌入 FastAPI BackgroundTask，十行內整合 100+ 通道；ntfy 補上手機端 push，兩者合計 <100MB、全本地零雲費。
ML 追蹤 / 評估 / 排程
★MLflow ＋ Ragas/DeepEvalApache-2.0
backend store 直接指向現有 pg16，Ollama 可當 judge LLM，內建 RAG 評估指標；搭 Ragas/DeepEval 做 faithfulness/relevancy 把關，單機零額外 infra。
03

五位專家共識

獨立視角 · 第二意見 · 落地約束

1行為學習 / LTR 架構師

  • 用 intent-strength 分數，7 個 criteria 直接當排序特徵
  • cold-start 先 LogReg+L2，200+ 樣本後換 XGBoost
  • 可解釋用 SHAP（非 LIME）
  • 行為強度標籤權重：feasible 1.0 > star≥4 0.6 > saved 0.3 > dwell>30s 0.15 > open 0.05

2Agentic RAG 架構師（本地優先 · 防幻覺）

  • _format_answer 換成 Ollama /api/chat 串流
  • 5 工具 ReAct：tender_search / similar / document / feasibility_hint / keyword_weights
  • MAX_TOOL_ROUNDS=3，逾時走 fallback
  • [src:ID] 引用驗證：生成的標案 ID 必須在證據內

3自動推播工程師

  • cold start 規則先於 ML
  • 疲勞控制：72h cooldown ＋ ≤5/day ＋ 可 dismiss
  • 通道：in-app → Email digest → Telegram（LINE Notify 2025 已停）
  • push_log UNIQUE 約束保證冪等

4資料 / MLOps 工程師

  • 特徵用 JSONB 快照（非 Feast）
  • 用 SQL 時間切分回測，初期不上 MLflow
  • keyword_weight_revisions 供回滾
  • 排程用 APScheduler（非 Celery）；混 10% exploration 避免回饋迴路偏差

5產品互動 / 意圖捕捉架構師

  • accept/skip 軟提示原因標籤（高分案略過才升級為 modal）
  • 新增 score-correction 事件讓使用者親手塑造評分
  • assistant 回應加 intent_hint（history_match / agency_relation…）
  • 補強訊號密度：tag_click / scroll_depth，Zod 驗證 payload
