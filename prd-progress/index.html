SECTION 02 — STACK & DEVIATIONS

技術棧與架構偏移

與原始 PRD §5 的差異，皆為刻意選型、非臨時湊合。

範圍實際採用偏移原因
前端 Vite 8 + React 19 + TypeScript（strict）+ Tailwind v4 + react-router-dom 7 原訂 Next.js；本期為內部工具＋demo，無 SSR 需求，Vite 啟動／建置快。日後若需 SSR/SEO 再評估遷移。路由為 BrowserRouter 真實路徑。
後端 FastAPI + SQLAlchemy 2.0 async + psycopg 3 + Pydantic v2 + PostgreSQL 16 + pgvector 符合原 §5 規劃；embeddings 用本地模型（bge-m3＝1024 維、HNSW cosine）。皆 brew 原生、無容器（本機）／Docker（Railway）。
預覽 vite dev（:5173，HMR）／靜態 build（:8771） 開發期優先用 vite dev；靜態 build 驗證需 rebuild ＋ cache-bust，容易誤判「改了沒生效」。
正式部署 Vercel（前端）＋ Railway（後端 Docker）＋ Supabase 新加坡（ajltwjkegmbzethwgbje） 2026-07-02 前曾誤指 Production Branch 至已關閉分支，已修正為 main；PR #10 建置修復合併後 main 恢復可部署。

SECTION 05 — ASSISTANT BRAIN PROVIDERS

大腦 Provider 與學習迴圈

開發期單機單操作者 → 全域單列設定（assistant_brain_config id=1，get-or-create）。依 config.provider 分派，未知 → BrainError。

PROVIDER 01

ollama

本機模型直連
  • 包現行 llm.stream_chat
  • 逐塊 yield delta（增量）
  • 本機模型可換（如 bge-m3）
  • Railway 容器無 Ollama，正式環境不使用
PROVIDER 02

cli

Headless agentic CLI 為大腦
  • 目前支援 claude -p … --output-format stream-json
  • 已注入 tender-ai-brain MCP，全自主呼叫工具
  • tool_use → progress 暫態（如「查詢中：search_tenders」）
  • Railway 容器無 claude 執行檔 → 優雅退回罐頭模板
PROVIDER 03

byok

自帶金鑰走雲端（正式架構）
  • Anthropic messages stream 協定
  • 指向 OpenRouter Anthropic 相容端點
  • byok_base_url 不可含 /v1；模型帶 anthropic/ 前綴
  • 2026-07-02 實測真實生成，正式環境預設
祕密隔離（紅線）
BYOK 金鑰本體只進 .env（settings.anthropic_api_key）；/settings/brain 只讀寫非密欄位，byok_key_set 由 .env 即時推導，永不回傳金鑰本體。CLI 切片完全不碰任何祕密；Layer B 邊界由 MCP 工具輸出層把關（去識別化／白名單），非靠 prompt 組裝。

SECTION 10 — OPEN QUESTIONS

未決議題

尚待拍板的方向性問題，非單純技術債。

#Question · 議題Context · 背景與選項
Q1 清單真分頁化要走 cursor 還是 offset？ offset 實作簡單但大資料量效能較差；cursor 對前端排序/篩選互動要求較高，需先定案排序穩定性。
Q2 CLI 大腦 provider 是否要在正式環境下線？ Railway 容器沒有 claude 執行檔，正式環境預設已切 byok；CLI 仍是本機開發期最自主的選項，去留需權衡維護成本。
Q3 語意搜尋的 🐛 標記是否可正式拿掉？ 2026-07-02 已灌入 2036 筆向量並通過正式環境驗證，但尚未有長時間穩定觀察，建議再觀察一段時間再改標記。
Q4 登入 Phase 2（session/token）排入哪個里程碑？ 目前輕量版可用但非長久之計，需評估與其他 P0/P1 項目的排序。
Q5 助手 Phase 3／Phase 4 優先序如何排？ 情境檢索（證據可信度）與留存（使用黏著度）都重要，需視近期使用回饋決定先後。
Q6 白名單未來若開放外部邀請註冊，共享範圍與具名規則如何調整？ 目前合作範圍＝@hqdesign.tw 白名單；若擴大需重新定義 Layer B 揭露邊界與具名機制。
Q7 本機 Windows 排程與舊個人 repo 何時正式退役？ 需先完成雙軌驗證（HQ 案源開發 W2），目前仍雙軌並行以確保報表不中斷。
