# Tender AI 整合視覺計畫

<Callout id="status-2026-06-25" tone="decision">

**狀態（2026-06-25）：Phase 1 詳情改版已落地並再演進。** 標案詳情已從窄版單欄升級到完整詳情頁 `/tenders/:id`，且 2026-06-24 一批進一步改為**常態性規格表**＋後台**團隊欄位顯示設定**（`DetailFieldVisibilityConfig`），全站套用 **Knowvio** 設計（淺色預設＋橙色主色、分層 elevation、ease-out 動效）。可行性 `score + breakdown` 顯示 contract 維持不變。本計畫保留為設計脈絡與責任邊界依據；**最新落地現況以 `PRD.md` §13（2026-06-25 快照）與 `docs/governance/05` 為準**，連線驗收（PCC／Ollama／向量）仍待能連線的環境補跑。

</Callout>

本計畫的近期交付是把現行窄版標案詳情升級為寬版雙欄決策介面，同時保留既有繁體中文預設與 `EN／中` 語系切換。中期則讓文件與已落地的 revision-first 後端重新對齊，為 citation-aware RAG、行為學習與可解釋推薦保留正確邊界。

完成定義：

- 詳情 Dialog 在 desktop 為資訊主欄 + 行動側欄，mobile 自動回到單欄。
- 可行性分數、關鍵字命中、北部限定、當日新案與 URL 篩選可由純函式測試覆蓋。
- 評價與轉發沿用既有 fire-and-forget API 模式；後端未提供資料以明確「待補」呈現。
- 所有新增 UI 文案都有 `zh`／`en` 對應，繁體中文仍為初始語系，頂部 `EN／中` 按鈕可切換並持久化。
- 繁體中文 UI 僅使用 `Noto Sans TC`；英文使用 `Inter`／`SF Pro Text` 等非襯線字，數字與程式碼使用 `JetBrains Mono`／`SF Mono`。
- Wireframe 採極簡直線與穩定幾何，不使用 rough／抖動／手寫感；統一 16px 圓角，資訊層級以 Bento 卡片、間距、邊框與背景分區建立，並允許**些微陰影**（如 `0 1px 2px rgba(0,0,0,.06)`）強化卡片分區，但禁止濃重投影或假深度。
- `npm run build`、`npm test` 與真實瀏覽器操作流程通過，並回填 PRD 開發狀態。

## 執行順序

### 1. 建立測試護欄

沿用 Vite／TypeScript 現況，新增 Vitest `node` 環境與 `@` alias。先以 smoke test 驗證 harness，再讓後續三個純函式模組各自有正常、邊界與錯誤輸入測試。

### 2. 建立單一計算來源

新增 `keyword-hits.ts`、`feasibility.ts`、`url-filter.ts`。可行性計算只呼叫共用 keyword matcher；URL 只序列化非預設值，解析失敗回到 `DEFAULT_FILTER`。預算以整數 TWD、截止日以已存在的 `daysLeft()` 為準。

### 3. 接入 store 與 API helper

在 `app-data.tsx` 以 memo 建立 `feasOf`／`keywordHitsOf`，供排序與詳情共用，避免顯示與列表排序分歧。`api.ts` 依 `postSave`／`postAccept`／`postNote` 的既有模式加入 `postRate`、`postShare`，外部失敗不回滾本地互動。

### 4. 擴充共用詳情元件

在 `detail-bits.tsx` 增加來源／類別／城市標籤、可行性 badge + breakdown、截止警示、待補區塊與 5 星評價。元件只負責展示與事件，不再自行重算關鍵字或分數。

### 5. 改寫詳情 Dialog

`tender-drawer.tsx` 改為 `max-w-5xl` 寬版雙欄：主資訊 2/3、行動與社群 1/3；手機回到單欄。保留既有完整詳情路由與原文連結，新增評價、轉發、公開／私人本地狀態與清楚的待補區塊。

### 6. 完成篩選分享與雙語覆蓋

`filter-bar.tsx` 加入北部限定、當日新案與複製篩選連結。所有新增文案在 `strings.ts` 的 `zh`／`en` 同步增加；既有 `AppProvider`、`toggleLang()`、`saveLang()` 與 Topbar `EN／中` 按鈕直接重用。

### 7. 真實流程驗收與文件回填

先跑單元測、build、lint，再用 Vite dev server 驗證 Dialog、tooltip、POST、URL reload、語系 persistence 與 mobile 版面。驗收後更新 `PRD.md` 開發快照，記錄 Phase 1 完成狀態及 revision／attachments／annotations 的後端現況。

## 主要風險

- **語意風險**：暫時分數可能被誤認為 AI 模型；需顯示「估算」與 breakdown。
- **雙重詳情表面**：Dialog 與 `/tenders/:id` 可能逐步分岔；共用 `detail-bits.tsx`，但不在 Phase 1 重構整頁。
- **localStorage 與後端不一致**：Phase 1 接受樂觀本地狀態；多人可見與跨裝置同步另立 ticket。
- **文件漂移**：PRD、handoff、README 與實際 migration 版本不同；只在驗收後回填已確認結果。
- **無 Git 邊界**：沒有 worktree／commit 可回復；以小步驟、每步測試與精確檔案範圍降低風險。
