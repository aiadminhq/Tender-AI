目標讀者：要接手 codebase 的工程師、要對帳前後端契約的人、以及要判斷「哪些端點動到 Layer B 共享行為資料、對外邊界在哪」的把關者。它不是新功能提案——它把散落在程式與 15 份 spec 裡的契約收斂成一張可導航的地圖；少數仍待拍板的決策集中在文末 **Open Questions**。

### 認證與安全模型

兩道閘層疊：所有 `/api/v1/*` 預設掛 `require_api_key`（`main.py:83`），需要身分的端點再額外掛 `get_current_user`（Bearer）。

- **X-API-Key**（`core/security.py:22`）— header `X-API-Key`，比對環境變數 `APP_API_KEY`；**未設定時等於不啟用**（開發預設關閉）。
- **Bearer Token / Phase 2 HMAC**（`core/auth.py`）— 格式 `base64url(payload).base64url(HMAC-SHA256(payload, AUTH_SECRET))`，payload 為 `{uid, iat, exp}`；**無 session 表**、無狀態。`get_current_user()` 每次請求即時查 DB 確認 `whitelist_active=True`（否則 403），role 也每次撈新 → 支援近即時撤銷。`AUTH_SECRET` 未設時簽發/驗證回 503，但唯讀端點仍可服務。
- **密碼雜湊**（`core/security.py:32`）— `pbkdf2_sha256`，200,000 迭代、每帳號 16-byte 鹽，存為 `pbkdf2_sha256$<iter>$<salt>$<hash>`，定速比對。
- **CORS**（`main.py:40`）— 允許 `localhost:5173/5174` 與本機任意埠 regex（含 Claude Preview），`allow_credentials=True`。
