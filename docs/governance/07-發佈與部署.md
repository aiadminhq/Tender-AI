## A. 發佈前先決定三件事（決策表）

每次發佈先確認這三格。**「目前傾向」是預設起點，不是鎖死**；右欄寫明何時該改選。

| 決策                      | 選項                                                                                           | 目前傾向（2026-06-24）      | 何時改選別的                                                                            |
| ------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------- | --------------------------------------------------------------------------------------- |
| **① 發佈目標／對象**      | a) 公司內網、白名單同事試用<br>b) 對外公開可註冊<br>c) 單機／開發者自用                        | **a) 內網白名單試用**       | 同事用穩了、Layer B 對外隔離與鑑權都到位 → 評估 b；只想先端到端驗證 → c                 |
| **② 向量化基礎設施**      | a) 與 app 同機跑 Ollama<br>b) 指向內網另一台 Ollama host<br>c) 暫不開語意、只用關鍵字          | **a) 同機 Ollama `bge-m3`** | 伺服器算力不足或要多服務共用 → b；Ollama 還沒備好但想先上線核心篩選 → c                 |
| **③ 小助手大腦 provider** | a) `byok`（Anthropic API key）<br>b) `ollama`（本地 qwen）<br>c) `cli`（Claude Code headless） | **a) BYOK Anthropic**       | 要零外部成本且伺服器有 GPU → b；**只在登入好 Claude Code 的開發機**才用 c（伺服器勿用） |

## C. 部署步驟（分階段，每階段給選項）

> 順序為建議；冪等步驟（migration、seed、向量回填）可重跑。每階段標「對應決策」。

### C-1. 環境準備（對應決策 ②）

| 元件                      | 選項                                                                                                                                      | 推薦                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| PostgreSQL + pgvector     | a) `docker compose up -d`（用內附 [`docker-compose.yml`](../../tender-ai-backend/docker-compose.yml)）<br>b) 主機原生安裝 pg16 + pgvector | a)：一鍵、版本一致                         |
| Ollama（決策②a/b 才需要） | 主機裝 Ollama → `ollama pull bge-m3`（向量）<br>決策③b 另需 `ollama pull <chat 模型>`                                                     | 與 app 同機 → `OLLAMA_URL=localhost:11434` |
| Python runtime            | venv / 容器，Python 3.12                                                                                                                  | 跟開發一致                                 |

```bash
# 範例（決策 ②a：同機 Ollama）
ollama pull bge-m3                       # 1024 維，勿換；換模型要出 migration 重嵌
cd tender-ai-backend && docker compose up -d   # 起帶 pgvector 的 pg16
docker compose ps                        # healthy 後再 migrate
```

### C-2. `.env` 正式設定（對應決策 ②③）

> 範本見 [`app/core/config.py`](../../tender-ai-backend/app/core/config.py) 的預設值。**預設僅供本機開發，正式必覆寫**。
> 祕密（API key、DB 密碼）只進 `.env`（已 gitignore），不入版控。

| 變數                | 必填？        | 說明 / 彈性                                  |
| ------------------- | ------------- | -------------------------------------------- |
| `DATABASE_URL`      | 🔴            | 覆寫預設密碼為強密碼                         |
| `ANTHROPIC_API_KEY` | 決策③a 必填   | BYOK 大腦用；決策③b/c 可空                   |
| `OLLAMA_URL`        | 決策②a/b 必填 | ②a＝`http://localhost:11434`；②b 填內網 host |
| `EMBED_MODEL`       | 選填          | 預設 `bge-m3`；換要重嵌                      |
| `CHAT_MODEL`        | 決策③b 相關   | ollama 大腦用                                |
| `APP_API_KEY`       | 🟡 建議       | 預設空＝不保護；內網也建議設                 |
| `CORS_ORIGINS`      | 🔴            | 改為內網前端網址，移除 localhost             |
| `CORS_ORIGIN_REGEX` | 🔴            | 正式環境**留空**，只認白名單                 |

### C-3. 資料庫遷移 + seed

```bash
alembic upgrade head            # 13 migration；CREATE EXTENSION vector 在內
# seed 白名單帳號（9 名 @hqdesign.tw）— 依現有 seed 腳本/指令
```

### C-4. 向量化全量回填 + 驗證（對應決策 ②；②c 跳過）

```bash
python -m app.jobs.embed_tenders     # 全量嵌入（需 Ollama 可達）
# 驗證：開 /search 抽幾筆查詢，確認檢索結果合理
```

> **批次抓取期間先不向量化**（避免讀到半抓取狀態）。語意品質沒驗過前，`/search`、`/evolution` 可先用 feature flag 關閉，等驗證 OK 再開（決策②c 的退路）。

### C-5. 大腦 provider 設定 + 驗證（對應決策 ③）

兩種設法，二選一：

| 方式               | 做法                                                                                                                                                                 | 適用                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| **執行期（推薦）** | 登入 admin → 設定頁小助手大腦，選 provider（③a＝BYOK / `claude-opus-4-8`）。走 [`brain_config.update`](../../tender-ai-backend/app/services/brain_config.py)，免改碼 | 一般發佈             |
| **改預設**         | 把 [`brain_config.py`](../../tender-ai-backend/app/services/brain_config.py) `get_or_create` 預設 `cli` 改成目標 provider，全新 DB 開箱即用                          | 想讓乾淨環境免手動設 |

> ⚠️ 預設是 `cli`，**伺服器上 spawn 不到 `claude` 會退回罐頭模板**（HTTP 仍 200、不掛站）。發佈務必主動設成 ③a/b。
> 驗證：問小助手一題，確認回真實答案而非模板。

### C-6. app 常駐（🔴 目前缺，需先補；對應任一目標）

> 現況**沒有 app 層部署產物**。三選一，依維運偏好：

| 選項                    | 說明                                        |
| ----------------------- | ------------------------------------------- |
| a) Dockerfile + compose | 與 DB 同 compose、最可攜；要新寫 Dockerfile |
| b) systemd service      | 主機原生跑 `uvicorn`，輕量；要寫 unit 檔    |
| c) supervisor / pm2     | 已有 process 管理習慣時                     |

```bash
# 共通：正式啟動指令（範例）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers <N>
```

### C-7. 前端 build + 服務

```bash
cd tender-ai-frontend
# 設定 API base 指向後端內網位址、VITE_USE_API=true
pnpm build           # 產出 dist/
# 以 nginx / 靜態服務 / 同源反代 提供 dist/
```

## E. 回退（Rollback）

> 選一條最快復原的路；資料層永不破壞性回退。

| 情境               | 做法                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| app 出錯           | 切回前一版映像／commit 重啟；DB 不動                                    |
| migration 出錯     | `alembic downgrade <rev>`（先確認該 migration 可逆）                    |
| 向量品質差         | 關 `/search`、`/evolution` feature flag；資料保留、重跑 `embed_tenders` |
| 大腦 provider 異常 | 設定頁切回另一 provider；最差自動退模板，不需手動                       |
| DB 資料            | `docker compose down` **不清卷**；只有 `down -v` 才清（謹慎）           |

## F. 發佈後維運

- **批次排程**：抓取、`enrich`、`embed_tenders`、`self_evolve`（consent-aware 閘：團隊線樣本 ≥50 且有新增才重學）、推播 digest——依需要排 cron/排程，注意「抓取期間不向量化」。
- **金鑰輪替**：`ANTHROPIC_API_KEY`／`APP_API_KEY`／DB 密碼定期換，只改 `.env` 重啟，不入版控。
- **健康檢查**：`GET /health` 接內網監控；前端自動健檢為待補項。
- **備份**：DB 定期備份（pg_dump）；向量可由 Layer A 重算，但備份省回填時間。
