# 04 ｜ 訓練資料串接規範（Training Data Standard）

> 先讀 `00-總覽與心智模型.md`。
> 目標：讓「使用者行為 → 學習 → 更準的推薦」這條迴圈，可重複、可稽核、守得住隱私。

---

## 1. 資料流（誰餵誰）

```
使用者操作（收藏/評分/略過/註記）
        │  寫入 Layer B：events / evaluations / annotations / tender_user_state
        ▼
learn_keywords.py（TF 關鍵字分析、類別/預算/機關特徵）
        │  產出 Layer C：keyword_weights（含 support 樣本數）
        ▼
evolution.py（學習迴圈，寫稽核 evolution_logs / keyword_weight_revisions）
        ▼
前端顯示：關鍵字 tag、可行性分數、推薦理由（SL2 / SL3）
```

---

## 2. 餵資料的規格

| 項目 | 規範 |
| --- | --- |
| **來源** | 只能來自 Layer B 的真實互動，不得人工塞造假樣本充數 |
| **隱私** | Layer B 不得進向量 metadata、不得回公開欄位；學習產物（Layer C）不得反推出個別使用者 |
| **最小樣本** | 每個關鍵字權重需記錄 `support`（樣本數）；低於門檻只供觀察、不上線影響排序 |
| **版本/稽核** | 每次學習都要寫 `keyword_weight_revisions` 與 `evolution_logs`（時間、觸發、指標、準確率變化） |
| **可重算** | Layer C 必須能由「Layer A ＋ Layer B」重新跑出，禁止只存結果不存來源邏輯 |
| **顯示契約** | 不論底層是規則或模型，前端永遠收 `score + breakdown`，UI 顯示「估算／理由」，避免被誤認為 AI 定論 |

---

## 3. 上線前的品質門檻（建議）

- 跑交叉驗證，記錄準確率；新一輪若**準確率下降**則不採用並回報。
- 類別（category）目前是最強訊號，已近 100%；**預算門檻與機關屬性**為下一步要補的特徵。
- 任何會改變排序權重的學習結果，需經一次人工抽樣檢視才上線。

---

## 4. 與 knowledge（領域知識）的關係

- 本檔談的是「**從使用者行為學**」（Layer B → Layer C）。
- 另一條是「**從文件學**」：`knowledge/*.md` → `ingest_knowledge.py` → `knowledge_chunks`，供 AI 助理（SL1）做 RAG 接地。
- 兩條來源不可混淆：行為資料是私人的（Layer B），知識文件是公開可重建的（屬 Layer A/C 範疇）。
