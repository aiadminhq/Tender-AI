## C. 本地跑起來

**前端**（mock 模式可零後端）：

```bash
cd tender-ai-frontend
pnpm install
pnpm dev                       # http://localhost:5180
# 純 mock：VITE_USE_API=false pnpm dev
```

**後端**（需 PostgreSQL16+pgvector、Ollama）：

```bash
cd tender-ai-backend
uv sync
docker compose up -d           # 起 pg16 + pgvector
uv run alembic upgrade head
uv run uvicorn app.main:app --reload   # http://localhost:8000/health
```

**前端接後端**：

```bash
cd tender-ai-frontend
VITE_API_BASE=http://localhost:8000/api/v1 pnpm dev
# 接上後，儀表板「示範資料」徽章會自動轉「即時資料」
```

## E. 真實資料注入（Layer A → 向量）

**資料來源**：Layer A 來自 `../tender-reports/reports/tender-*.html`（每日報表，repo 外、gitignore）。

```bash
cd tender-ai-backend
uv run python -m app.jobs.backfill          # 解析報表 → tenders/daily_runs/daily_tender（離線、idempotent）
ollama pull bge-m3
uv run python -m app.jobs.embed_tenders     # 灌 tender_vectors（解鎖語意/相似/AI 助理）
uv run python -m app.jobs.ingest_knowledge  # 灌 knowledge_chunks（RAG 接地）
# 詳情增補（需 PCC 網路）：
uv run python -m app.jobs.enrich_details
```

**向量狀態三態檢查**：

```sql
select count(*) from tenders;          -- 已處理（Layer A）
select count(*) from tender_vectors;   -- 0=未訓練；>0=已訓練
select count(*) from knowledge_chunks; -- 知識庫
```

注入後重跑 `pnpm shots` 即為真實資料畫面（注意：真實畫面屬合作範圍，勿對外散佈）。
