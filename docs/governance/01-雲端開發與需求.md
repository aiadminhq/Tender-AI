# 01 ｜ 雲端開發與需求（Claude Code on the Web）

> 先讀 `00-總覽與心智模型.md`。本檔說明在雲端環境怎麼下需求、追進度。

---

## 1. 雲端環境的本質（先理解，避免誤會）

- 雲端是**用完即丟的容器（ephemeral container）**：repo 是當下從 GitHub 重新 clone 的，session 結束就回收。
- 👉 **沒 commit / push 的東西＝不存在**。任何成果一定要進 GitHub branch 才算數。
- 雲端的 GitHub 權限**只限定 `aiadminhq/tender-ai`** 這個 repo。
- 雲端**連不到**外部 PCC 招標網與本機 Ollama；涉及「真的去抓網頁／真的算向量」的工作，需在能連線的環境驗證，雲端只能用 backfill 資料與 mock 測試。

---

## 2. 下需求的標準動作

1. 用下方「需求單範本」開一張需求（GitHub Issue 或對話皆可，格式一致即可）。
2. 指定**目標分支**（預設 `claude/<主題>`，例：`claude/busy-sagan-gm197s`）。
3. 講清楚**驗收條件**與**不可動範圍**。
4. AI 完成後 commit / push 到指定分支，並用「白話三段式」回報（見 `05-進度與白話術語.md`）。

> 💡 一張需求單只解一件事；太大就拆成多張，避免「一次改一堆檔案」難驗收、難回復。

---

## 3. 需求單範本（複製這段去填）

```
【需求單】
標題：（一句話，白話）
功能代號：SLx / Px / Layer? （對應 00 總覽；沒有就寫「無」）
目標（白話）：我想達成什麼，為什麼

範圍：
  - 會動到的模組／檔案：
  - 明確「不可動」的部分：（例：不改 alembic migration、不改 scraper 核心）

驗收條件（做到什麼算完成，盡量可量測）：
  - [ ]
  - [ ]

依賴 / 前置：（需要 Ollama？需要本地端先給資料？）
優先級：高 / 中 / 低
目標分支：claude/____
```

---

## 4. 雲端能做 / 不能做（快速對照）

| 可以在雲端做 | 需要能連線的環境（本地/正式） |
| --- | --- |
| 改前端、改後端程式邏輯 | 真的去抓 PCC 招標網頁 |
| 跑 offline 單元測試、用 backfill/mock 驗證 | 真的呼叫 Ollama 算向量／嵌入 |
| 寫文件、改設定、重構 | 連真實資料庫做整合測試 |
| 在指定分支 commit/push | 對外部署 |
