## 一頁速覽（先看這個）

一句話定位：**Tender AI 是一個「幫人篩選政府標案、並會越用越聰明」的系統。**

它由兩個程式包組成：
- `tender-ai-backend/`：資料與 AI 大腦（Python / FastAPI）。
- `tender-ai-frontend/`：人看的畫面（React / TypeScript）。

| 你是誰 | 最該先看哪份 |
| --- | --- |
| 老闆 / 非技術夥伴 | `05-進度與白話術語.md` |
| 下需求的人 | `01-雲端開發與需求.md` |
| 寫程式的人 / AI | `02-本地雲端同步.md`、`03-命名與目錄規範.md`、`04-訓練資料規範.md` |

## 1. 資料三層（Layer A / B / C）— 全專案最重要的邊界

| 層 | 白話 | 內容 | 可不可以公開 | 能不能重建 |
| --- | --- | --- | --- | --- |
| **Layer A** | 「公開的標案資料」 | 抓回來的標案本體、每日快照、修訂版本 | ✅ 可公開 | ✅ 可從原始 HTML 重建 |
| **Layer B** | 「使用者的私人行為」 | 誰收藏、誰評分、誰略過、誰寫了註記 | ❌ **永不公開、永不進向量 metadata** | ❌ 不可重建（毀了就沒了） |
| **Layer C** | 「學出來的知識」 | 關鍵字權重、向量、推薦理由 | ⚠️ 衍生物，可重算 | ✅ 由 A＋B 重新學出 |

> 🔒 **鐵則**：任何工作只要碰到 Layer B，就要在需求單與 PR 說明寫清楚「資料如何隔離」。
> Layer B 不得寫入任何會公開的檔案、log、向量 metadata、或回傳給前端的公開欄位。

## 2. 功能代號（沿用既有命名，請勿另創）

| 代號 | 白話名稱 | 目前狀態 |
| --- | --- | --- |
| **SL1** | AI 助理對話 | 已串接，待向量資料灌入後才真正好用 |
| **SL2** | 可行性分數 | 過渡版（用 tier 估算），待模型 |
| **SL3** | 可解釋推薦理由 | 已串接 |
| **SL5** | 主動推播 | 已串接 |
| **SL6** | 學習進化迴圈 | 已串接（MVP） |
| **P1–P5** | 開發階段（P1 基礎→P5 進階 ML） | 目前在 P2/P4 之間 |

> 命名原則：**對外（給人看）用白話名稱，對內（程式、commit、需求單）用代號**，兩者一一對應，不得新增同義詞。
